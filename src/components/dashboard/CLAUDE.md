# components/dashboard/

Dashboard presentation, ported from the armada-app design mockup. Composed by `pages/Dashboard.tsx` into a centered ~420px card stack (BalanceCard → DepositTooltip → RecentActivityList). While the wallet is locked the stack is `LockedDashboard`; while the first sync loads, the balance spot is `SyncCard`. Presentation only — all data/actions are wired in `Dashboard.tsx`.

## Contents

| Component / file | Purpose |
|---|---|
| `BalanceCard` | The "Private USDC" card: header (shield badge · label · eye/hide toggle), animated balance numeral, action row (SEND · `+` deposit · `↓` receive · `⋯` more menu = Earn/Withdraw/activity toggle), optional vault position bar. |
| `SignInCard` | The balance spot while locked: "Your private USDC", what signing in does, and one button ("Connect wallet" / "Sign in" / a disabled "Reconnecting…" while wagmi reconnects). Optional lines: the lock reason (`lockNoteFor`: idle minutes / tab in the background / "You locked Armada."), a pay link's context (`payNoteFor`: "Sign in to pay 25.00 USDC to 0zk…"), the wallet's public USDC ("…sign in to shield it", hidden at 0). A "How this works" toggle. No action tiles — the sign-in button is the only action. At least the signed-in BalanceCard's height (no vault bar; 284px, 260px on mobile — measured, so update `SignInCard.module.css` if BalanceCard's layout changes), with the button at the bottom; extra lines grow it. |
| `LockedDashboard` | The locked stack: `SignInCard` and `RecentActivityList` with `locked` — the same "Recent activity" heading over "Sign in to see your activity." (history is encrypted until sign-in). No banners, and never a cached balance or history. |
| `SyncCard` | The balance spot until the first SDK balance is known (G-11): "Syncing… N%" progress (no figure), a caption to keep the tab open, and on a first sync on this device "…this first sync takes longer". Shield and Request work; Send and Earn are disabled with the reason. A failed sync shows "Sync interrupted" with Try again, then "Still not loading?…" + Discord after a failed retry. The activity preview shows under it. |
| `RollingBalanceValue` | Odometer roll for the balance numeral (intro from zero; re-roll from previous value on change). A re-roll pads the shorter value to line up the decimal point; those padding columns fold to zero width instead of showing zeros, so the row starts as the old value and ends as the new one. `onRollEnd` fires once the last staggered column lands, so a caller swapping in a static value doesn't re-derive the timing; `rollSettleMs(value, { mode, fromValue })` gives the same settle time for a caller that ends several rolls on one timer (BalanceCard ends the balance + vault re-rolls on the later of the two). Also drives the amount roll in `deposit/DepositAmountCard` and `VaultPositionBar`. |
| `BalanceScrambleValue` | Steady-state hide/reveal scramble for the balance + activity amounts. |
| `VaultPositionBar` | Vault (yield) position row inside BalanceCard; shows earned + APY ("Earning X.XX% APY", or "—" until the rate loads — never a stand-in rate). |
| `SendButton`, `ShieldedUsdcBadge`, `TokenBadge` | Small presentational pieces of the card. |
| `DepositTooltip` | First-run "Make your first deposit" callout under the card (empty state). |
| `RecentActivityList` | Activity list — icon-badge rows with scrambled amounts + per-item peek. `locked` (before sign-in): the heading, no "View all", and a muted clock + "Sign in to see your activity." straight on the background in the row label's type. `variant="preview"` (dashboard, flat, with "View all" → the `ActivityAllPanel`) or `variant="full"` (inside the panel), which sections its rows by date under headings: Pending (whatever the date), Today, Yesterday, then one per month ("November"; "December 2025" for an earlier year) — `activityGroups.ts::groupActivityByDate`, local calendar days. |
| `ActivityAllPanel` | "All activity" SidePanel/BottomSheet (titled "All activity") — kind filters + search over the full list (no matches → "No transactions match your filters." + "Clear filters", which resets both); a row click opens the `ActivityReceipt`. Replaces the retired `/history` page. `Dashboard` feeds it the full activity list capped at `ACTIVITY_PANEL_MAX` (500, no virtualization); `truncatedCount` surfaces a "showing latest 500" note only when history exceeds the cap. The inline dashboard preview is a separate `ACTIVITY_PREVIEW_MAX` (8) slice. |
| `ActivityKindFilters` / `ActivitySearch` | Toolbar controls for the panel (kind chips + search); predicates in `activityFilters.ts`. The search matches part of the tx hash or the counterparty address (`DashboardActivityItem.address`: a send's recipient, a received payment's disclosed sender), and a typed number matches the amount by its leading digits ("12" → 12.50, 120.00) — amounts only, since most hashes contain every digit. While balances are hidden a number is searched as text instead, so searching can't reveal an amount (the placeholder drops "amount"). *(These + `ActivityAllPanel` live nested under `RecentActivityList/`, not as top-level dashboard siblings.)* |
| `BalanceActionButton` | Labeled round action tile in the BalanceCard action row (Shield / Send / Request / Earn). |
| `DashboardScrollTopFade` | Top-edge scroll fade over the card stack when activity scrolls. |
| `ActivityReceipt` | Per-tx receipt overlay — reopens a past tx's confirm-step summary (date/time, amount, fees, to/from) by reconstructing the review-summary props from its record. For a non-settled record it drives the FlowShell status from the outcome and prepends a category-aware failure banner (shared `lib/tx/errorCopy.ts`, ending with where the USDC is when that's certain — `fundsNote` — and, unless the user cancelled, a plain "Get help on Discord" link, `config/support`); the "Date and time" row is omitted since it never confirmed, and fees / totals read "—" when the tx moved no money (`lib/fees/txFigures::moneyMoved` — a cross-chain tx whose burn confirmed before its delivery failed still shows what it was charged). All figures come from `lib/fees/txFigures`; the Dashboard shows a send to the wallet's own 0zk as a merge (`lib/tx/selfSend.ts`). A pending record adds the flow's live stepper (`ActivityReceipt/ReceiptProgress` → `tx/processing/TransactionProgressDisclosure`, collapsed to the current step, from `buildProcessingView`, with a polite screen-reader announcement) between the amount and the summary, where a failed record shows its banner. With the active row's usual-time chip, and under it the slow callout (`tx/processing/TxTimingNote`) and, while a spend is still building its proof, `tx/TxCancelButton`. It eases in after the body's slide-in; when the record settles it holds the finished step (~600ms) then collapses (height + fade, the summary sliding up), and a failure collapses at once while the banner fades in. Instant under reduced motion. While open, the receipt's tx raises no toast / header notice (`Dashboard` registers it via `useTxInView`). A received payment renders `ReceivedSummary`. A cross-chain tx adds "View delivery on {chain}" (`tx/DeliveryTxLink`) under the summary — the main "View on explorer" button is the source-chain tx. Under that, once there's a hash, a "Transaction" line with the shortened hash and a button copying it in full (`ui/CopyAddressButton`); then "do it again" ("Send again" / "Unshield again" / "Shield again" / "Deposit again" / "Withdraw again", `repeatIntent.ts`) for a settled, failed or cancelled tx — it closes the receipt, then `onRepeat` hands the prefill (`state/ui::repeatIntentAtom`) to the flow, which opens on its amount step with it filled in. |
| `repeatIntent.ts` | `repeatIntentFor(record, ownWallet)` — the receipt's "do it again" prefill: a send's recipient + chain + amount (a public send to the own wallet repeats as an unshield, `isWithdrawToSelf`), a shield's source chain + amount, a vault move's direction + amount; null while pending or unknown (it may still go through — repeating could pay twice), and for a received payment or a merge. `repeatLabel` names the button, `repeatModalFor` the modal (and tab) it opens. |
| `ReceivedSummary` | A received payment's receipt table — date, "From" (only when the sender disclosed their 0zk; shortened with a copy button, `ui/CopyableAddress`), memo; no Fees or Total (the recipient pays nothing, and the amount is the headline). |
| `txActivityAdapter.ts` | Maps `TxRecord[]` → `DashboardActivityItem[]` (direction/sign/label — a `consolidate` record is a `merge` item whose amount is its fee — + a `status` bucket via `deriveActivityStatus`: `settled`/`pending`/`failed`/`cancelled`/`unknown`). Indeterminate codes (`POLL_TIMEOUT`/`DISMISSED`/`DUPLICATE_TX`), `expired`, and a network error (`RPC_ERROR`) once the tx was being sent → `unknown` (never "failed" — they may still have settled). `buildActivityItems(txList, requestLinks)` merges in created-payment-link rows. The data seam for the activity list; the row renders `failed` struck-red / `cancelled` struck-muted. |
| `dashboardFormat.ts` | Number-based `formatUsdcAmount` / `truncateArmadaAddress` / `formatTimeAgo` used by the ported (number-typed) components. Distinct from `@/lib/format` (bigint-based). `formatTimeAgo` is relative for the first week, then an absolute date ("Oct 3", + year when not this year); the activity row's time carries the full date/time as a hover `title`. |
| `vaultEarnings.ts` | VaultPositionBar's helpers — the APY label (`formatVaultEarningLabel`, via `lib/yield::formatApyPercent`), the earned-amount format, and `accruedVaultYieldRaw`. |

Shared primitives `IconButton`, `Tooltip`, `BottomSheet` live in `@/design`; the hooks (`useMobileLayout`, `useEscapeKey`, `useBodyScrollLock`, `useDashboardBackground`) live in `@/hooks`.

## Conventions

- **Presentation only.** These components take numbers/strings/callbacks; `Dashboard.tsx` reads the atoms/hooks and adapts. Don't reach into atoms here.
- **The mockup is the source of truth.** These are ports — restyle via tokens, keep motion parity; don't diverge from the mockup without a reason.
- Empty states are first-class (RecentActivityList renders "No activity yet"; the DepositTooltip is the balance-0 first-run affordance).

## Deviations from the vendored mockup

- `RollingBalanceValue` re-rolls fold the decimal-alignment padding away instead of rendering it as zeros (`05.0`, `01.74`) that vanish when the roll ends. The mockup shows the zeros; they read as a jump at the hand-off to the static value.
- `VaultPositionBar` reads "Earning X.XX% APY" (mockup: "X.X% APR", with a hard-coded 4.2 default). The number is the vault's net APY (`useYieldRate().apyBps`), shown with the same label and two-decimal format as every other APY surface (`lib/yield::formatApyPercent`), and an unknown rate renders "—" (#124).
- `formatTimeAgo` switches to an absolute date after 7 days (mockup: "N weeks ago" with no upper bound, so a year-old tx read "52 weeks ago").
- `BalanceCard.module.css` `.armadaAddress` uses the sans UI font, not Geist Mono. The vendored mockup copy (cloned at the start of the redesign) specifies `mono-sm`, but the current designer mockup renders the shielded address in sans — the clone is likely stale. Re-cloning `.context/armada-app` may surface other drift.

## Known follow-ups

- `useDashboardBackground` is a stub returning `'gradient'`; the solid/gradient toggle UI is not ported.
- The `Request` action opens the request-via-link flow (`components/request/RequestModal`).
- `VaultPositionBar` "earned" figure = accrued vault yield, computed by `Dashboard` as `accruedVaultYieldRaw(txList, currentVaultValue)` (vault value − net settled deposits/withdrawals from history; `vaultEarnings.ts`) and passed as `earnedAmount`. Gated on `vaultLoaded && !gated && historyRecovery.state === 'idle'` so it only shows once history has settled — otherwise it falls back to the obvious `???` placeholder rather than a wrong number (a mid/failed recovery scan would under-count deposits).
